## 3. 구현 방식 (모두 [Claude 구현 판단])

- **PWA(설치형 웹앱)**: 빌드 도구 없이 순수 HTML/CSS/JavaScript(ES 모듈)로 만들었습니다. 기존 저장소가 GitHub Pages로 배포하는 웹앱이라 같은 방식을 택했습니다.
- **서버 없음**: 모든 데이터는 기기 브라우저의 `localStorage`(키 `choco-diary-v1`)에 저장합니다. 설정에서 JSON 파일로 백업하고 불러올 수 있습니다.
- **오프라인**: `sw.js` 서비스 워커가 앱 파일을 캐시합니다(같은 출처 파일은 네트워크 우선, 글꼴과 CDN은 캐시 우선).
- **글꼴**: Google Fonts의 Single Day(제목·말풍선)와 Noto Sans KR(작은 글자)를 씁니다.
- **아이콘**: 바나나 수트를 입은 말티즈 캐릭터 SVG로 만든 PNG입니다(32, 180, 192, 512px).
- **리포트 이미지 저장**: 버튼을 누를 때 cdnjs에서 html2canvas 1.4.1을 불러옵니다.
- **카카오톡 공유**: 카카오 SDK(앱 키 필요) 대신 Web Share API를 씁니다. 휴대폰 공유 시트에서 카카오톡을 고르는 방식이고, 지원하지 않으면 텍스트를 클립보드에 복사합니다.
- **휴대폰 알림**: 앱을 열 때 새로 생긴 알림을 시스템 알림으로 띄웁니다(서비스 워커의 `showNotification`). 앱이 닫혀 있을 때 오는 푸시는 서버가 없어서 **지원하지 않습니다.**

## 4. 화면과 기능 (구현된 그대로)

### 4-1. 시작과 캐릭터 고르기 (`js/screens/petEdit.js`)
- 처음 실행하면 3단계로 진행합니다: 소개 → 캐릭터 고르기 → 이름과 기본 정보. 두 번째 동물부터는 소개를 건너뜁니다.
- 캐릭터 6종: 강아지(말티즈·푸들·골든리트리버), 고양이(치즈냥·검정냥·삼색냥)
- 털색 8가지: 흰색·크림·살구·갈색·초코·검정·회색·황금
- 기본 정보: 이름(필수, 최대 12자), 품종, 생일, 만난 날, 성별(남/여), 중성화(O/X)

### 4-2. 홈 (`js/screens/home.js`)
- 코인 표시, 알림 종(안 읽은 알림이 있으면 빨간 점), 설정 버튼
- 동물 이름을 누르면 여러 마리 중에서 바꿀 수 있습니다. 표시: "품종 · 나이 · 함께한 지 N일 째"
- 판자집 장면. 상점에서 산 장식(벽지·바닥·벽난로·방석)이 반영되고, 벽지나 벽난로가 없으면 바람 효과가 보입니다.
- 캐릭터는 9초마다 걷기와 앉기를 바꾸고, 밤(23~6시)에는 잡니다. 누르면 웃고 뛰면서 반응 멘트를 합니다.
- 랜덤 멘트(`js/lines.js`): 억울하지만 주인을 좋아하는 반말 말투. 시간대, 집 상태, 코스튬에 따라 바뀝니다.
- **청결도**: 시간당 0.6%씩 떨어집니다(하루 약 14%). 90% 미만이면 더러운 자국과 "청소하기" 버튼이 보입니다. 청소 보너스는 청결 70% 미만이면 +20코인("복귀 보상"), 90% 미만이면 +5코인입니다.
- 아래쪽 "○○와 대화하기" 카드를 누르면 채팅 기록으로 갑니다.

### 4-3. 채팅 기록 (`js/screens/chat.js`)
질문 순서(캐릭터가 묻고 버튼으로 답합니다):
1. 식사: 안 먹음 / 적게 / 보통 / 많이
2. (사료 칼로리가 입력돼 있고 "안 먹음"이 아닐 때) 사료 g 입력 → kcal 자동 계산 = g × kcal/kg ÷ 1000
3. (알레르기가 등록돼 있을 때) 간식 입력 → 알레르기 성분이 있으면 경고
4. 음수량: 적게 / 보통 / 많이
5. 배변: 정상 / 묽음 / 설사 / 변비 / 안 함
6. 산책(고양이는 "놀이"): 안 함 / 10분 / 20분 / 30분 / 1시간 / 직접 입력
7. (노령 모드일 때) 관절: 괜찮음 / 조금 / 많이 → 인지: 없음 / 가끔 / 자주
8. 특이사항(여러 개 선택): 구토 / 설사 / 발작 / 식욕부진 / 절뚝거림 / 기침 / 멀쩡함 / 기타 + 메모. 발작을 고르면 병원 연락 경고가 나옵니다.

- 음수량, 배변, 산책 질문은 설정에서 끌 수 있습니다.
- 과거 날짜도 캘린더에서 들어가 기록할 수 있습니다.
- **코인은 오늘 기록에만, 항목마다 한 번씩** 지급합니다: 식사·물·배변·특이사항 각 +2, 산책 +5(0분이면 없음), 관절·인지 각 +1, 하루 완료 +10.
- 알레르기 별칭 사전(`store.js`의 `ALLERGEN_ALIASES`): 닭고기 → 닭·치킨·chicken 등

### 4-4. 나의 동물 (`js/screens/pets.js`)
- 목록: 동물 카드, 질환·알레르기 칩, 최근 3개월 체중 미니 그래프, 가장 가까운 접종 D-day
- 상세:
  - 노령 모드 스위치. 기본은 자동이고 강아지 7살, 고양이 10살부터 켜집니다.
  - 체중 그래프(1/3/6/12/24/36개월), 체중 등록·삭제
  - 건강검진·접종: 마지막 날짜를 넣으면 다음 날짜와 D-day를 자동 계산합니다. D-3 이하는 빨강, 30일 이하는 파랑입니다.
  - 기본 주기: 심장사상충 약 30일 · 종합백신 365일 · 광견병 365일 · 건강검진 365일 · 내부 구충제 90일 · 외부 기생충 약 30일 · 스케일링 365일. 항목마다 주기를 직접 바꿀 수 있습니다.
  - 하루 권장 칼로리(참고용): RER = 70 × 체중^0.75에 계수를 곱하고 10단위로 반올림합니다. 계수는 강아지 중성화 1.6 / 미중성화 1.8, 고양이 중성화 1.2 / 미중성화 1.4, 노령 강아지 1.4 / 노령 고양이 1.1입니다.
- 정보 수정: 캐릭터 다시 고르기, 기본 정보, 질환 칩, 알레르기 칩, 주력 사료(이름·kcal/kg·원재료). 원재료에 알레르기 성분이 있는지 자동으로 확인하고, 동물 삭제도 할 수 있습니다.

### 4-5. 캘린더 (`js/screens/calendar.js`)
- 월 이동, 날짜 칸 표시: 밥·산책·특이사항·일정·접종 완료·예정
- "병원 리포트 공유" 배너: 최근 2주 변화 요약
- 날짜를 누르면 그날 기록, 일정, 접종이 나오고 "채팅 보기/기록하기"로 갈 수 있습니다.
- 일정 추가: 종류(병원/주사/약/미용/기타), 내용, 날짜, 시간. 삭제도 됩니다.

### 4-6. 병원 리포트 (`js/screens/report.js`)
- 기간: 1주 / 2주(기본) / 1개월 / 직접 지정
- 변화 감지: 특이사항별 횟수와 날짜, 음수량 "많이" 일수(직전 같은 기간과 비교), 식사 적음 일수, 배변 이상, 체중 변화(5% 이상이면 주의), 산책 평균, 평균 kcal
- 날짜별 띠 그래프(정상/특이사항/기록 없음)와 "진단이 아닌 참고 자료" 문구
- 이미지로 저장, 공유

### 4-7. 알림 (`js/screens/notifications.js`, 계산은 `store.js`의 `computeNotis`)
- 식사 기록 없음(8시 이후), 산책 기록 없음(강아지, 17:30 이후)
- 접종·약 D-3 이하(지난 것 포함), 오늘·내일 일정
- 주간 특이사항(최근 7일): 구토 2회 이상, 설사 2회 이상, 발작 1회 이상, 음수량 많음 3일 이상이면서 직전보다 증가, 식사 적음 3일 이상
- 청결 70% 미만, 보상 내역
- 오늘 / 어제 / 이번 주 / 이전으로 묶어 보여 주고, 모두 읽음을 지원합니다.

## 6. 검증한 것과 알려진 제한

검증(클라우드 세션):
- Playwright로 390×844 휴대폰 크기에서 시작 → 캐릭터 → 이름 → 홈 → 채팅 기록 → 상세(체중·접종) → 정보 수정(알레르기·사료) → 알레르기 간식 경고 → 캘린더 일정 → 리포트 → 상점 구매·미리보기 → 알림 → 설정까지 직접 조작했습니다. 자바스크립트 오류와 가로 넘침은 없었습니다.
- 코인 계산이 맞는 것을 확인했습니다(100 + 기록 23 − 방석 60 = 63).
- ESLint 검사를 통과했습니다.
- 설정 화면 카드가 눌려 잘리는 문제를 찾아서 고쳤습니다.

알려진 제한(README에도 적음):
- 서버가 없어서 기록은 기기에만 저장됩니다.
- 앱이 닫혀 있을 때 오는 푸시 알림이 없습니다.
- 사료 검색 DB가 없어서 칼로리와 원재료를 직접 입력해야 합니다.
- 얼굴 촬영 가이드는 미구현입니다.
- 리포트와 칼로리는 참고용이며 진단이 아닙니다.

## 7. 대화에서 논의한 것 중 결론이 안 난 것 [미결정]

1. **실제 사용자 데이터를 받는 서비스로 만들기**
   - 사용자 발언 **[사용자 결정]**: "진짜 사용자들의 데이터를 받는 앱을 만들 거라서 그래"
   - Claude가 안내한 내용(법률 전문가 검토는 받지 않음):
     - 지금 앱은 서버로 보내는 기능이 없어서, 서버 프로그램, DB(소규모는 SQLite), 로그인, 도메인과 HTTPS, 앱 수정이 필요합니다.
     - 이용자 데이터를 해외(오사카) 서버에 두면 한국 개인정보보호법의 국외 이전 의무(고지와 동의 등)가 생길 수 있다고 알려져 있습니다. 정확한 기준은 개인정보보호위원회 안내나 전문가로 확인해야 합니다.
     - 무료 서버 한 대는 장애, 회수, 백업, 보안 위험이 있습니다.
     - 서비스로 만든다면 개인정보처리방침과 이용약관, 동의 화면, 비밀번호 암호화나 소셜 로그인, 탈퇴 시 삭제, 백업, 앱스토어 개인정보 기재가 필요합니다.
     - 선택지로 ① 지금처럼 기기 저장 + 백업, ② 내 오라클 서버, ③ 서울 리전이 있는 관리형 서비스(AWS, Firebase, Supabase, 네이버 클라우드 등, 리전과 요금은 가입 전 확인 필요)를 제시했습니다.
     - Claude는 "오사카 무료 서버에는 사용자 데이터를 두지 말고, 먼저 꼭 받아야 할 데이터부터 정하자"고 권했습니다.
   - **사용자는 아직 어떤 방식을 쓸지 고르지 않았습니다.** 데이터 항목을 정리하는 작업도 하지 않았습니다.
2. **앱이 닫혀 있을 때 오는 푸시 알림**: 서버가 있어야 가능하다고 설명했고, 오라클 서버 활용 예시로 언급했습니다. 결정된 것은 없습니다.
3. **앱의 새 이름**: 정해지지 않았습니다.
4. **커밋 `54b3ecc`(스킬 4개)를 `main`에 넣을지**: 정해지지 않았습니다.

## 8. 관련 작업 환경 (앱 코드와 직접 관련은 없지만 대화에서 진행한 것)

### 8-1. 오라클 클라우드 무료 서버 [진행 중, 결과 미확인]
- 지역은 **오사카(ap-osaka-1, AD-1)**입니다. 사용자가 가입할 때 한국 지역이 선택지에 없어서 오사카를 골랐고, "일단 오사카로" 진행하기로 했습니다 **[사용자 결정]**. 홈 리전은 바꿀 수 없습니다.
- 서버 용도: 사용자가 처음 준 작업 양식의 예시가 "텔레그램 봇 하나를 24시간 켜 두기"였고(양식 칸은 비어 있었음), 이후 "봇을 두는 거 말고도 다르게 사용할 수 있어?"라고 물었습니다. Claude는 이 서버를 **봇과 연습용으로 쓰고 사용자 데이터는 두지 말 것**을 권했습니다. 사용자는 명시적으로 동의하거나 반대하지 않았습니다.
- 서버를 만드는 동안 고른 것:
  - 이미지: **Canonical Ubuntu 24.04** **[사용자 결정, Claude 권장]**
  - 모양: **VM.Standard.A1.Flex**(Ampere ARM). 처음에 4 OCPU / 24GB로 시도했습니다. 사용자가 "한 번에 크게 만들면 안 돼?"라고 물어서 크게 시도하기로 했습니다.
  - Security(Shielded instance): 끔(기본값)
  - 네트워크: 새 VCN `vcn-20261106-0920`, 새 공인 서브넷 `subnet-20261106-0920`(10.0.0.0/24). 공인 IPv4 자동 할당 스위치가 비활성이라 **"방법 A: 서버를 만든 뒤 VNIC에서 Ephemeral public IP를 붙이기"**로 하기로 했습니다 **[사용자 결정]**.
  - SSH 키: "Generate a key pair for me"를 골랐고 `Download private key`를 안내했습니다. 사용자가 실제로 내려받았는지는 답하지 않았습니다. **[미확인]**
  - 부트 볼륨: 기본 46.6GB
- 결과:
  - A1 4/24 → **Out of capacity**
  - 2/12로 줄임 → "Too many requests"(여러 번 누름) → 다시 **Out of capacity**
  - Claude는 **VM.Standard.E2.1.Micro(AMD, 1GB, Always Free)로 먼저 만들기**를 권했습니다. 그 뒤 진행 결과는 알 수 없습니다. **[미확인]**
- 사용자 제약 조건 **[사용자 결정]**: 오라클 콘솔 설정과 요금제를 바꾸지 말 것("Upgrade" 버튼 누르지 않기), 서버에서 sudo 실행 전에 먼저 물어볼 것, 비밀 키 내용을 출력하거나 복사하지 말 것.
- 클라우드 세션에는 ssh가 없고 22번 포트가 막혀 있어서, 접속은 사용자 컴퓨터에서 해야 한다고 안내했습니다.

### 8-2. Claude Code 확장 도구
- 클라우드 세션에서 설치한 스킬 4개: agent-browser, find-skills, design-taste-frontend, mcp-builder. 저장소 `.claude/skills/`와 `skills-lock.json`에 있고, 커밋 `54b3ecc`(`main` 미병합)입니다.
- GSD(@opengsd/gsd-core v1.20.1)는 클라우드 컨테이너의 `~/.claude`에 설치돼서 세션이 끝나면 사라집니다.
- agent-browser의 Chrome 내려받기는 클라우드 네트워크 차단으로 실패했습니다.
- omniroute 3.8.52는 클라우드 컨테이너에만 설치했습니다. `/v1/models`는 API 키가 필요해서(401) 검증하지 못했습니다. headroom과 claude-mem은 설치하지 않았습니다. 사용자는 이후 **자기 컴퓨터에서 직접 설치하기로** 했습니다 **[사용자 결정]**. 요청 조건은 기존 설정 덮어쓰지 않기, 중복 설치하지 않기, API 키 출력하지 않기, 하나씩 설치하고 검증하기입니다.
- Task Observer 스킬은 출처를 확인하지 못해 설치 방법을 안내하지 못했습니다.

### 8-3. 사용자 컴퓨터의 Claude Code 설치 [진행 중]
- 사용자 컴퓨터: **Windows**(버전 10.0.26200), 사용자 폴더 `C:\Users\User`
- 사용자는 **자기 컴퓨터에서 Claude Code를 직접 쓰고 싶다**고 했습니다 **[사용자 결정]**.
- 설치 결과: `C:\Users\User\.local\bin\claude.exe`(약 342MB, 2026-11-06 10:49)는 있는데, CMD에서 `claude`를 **인식하지 못합니다**(PATH 미등록).
- 마지막 안내: CMD에서 `powershell -NoProfile -Command "…"` 한 줄로 사용자 PATH에 `%USERPROFILE%\.local\bin`을 추가 → 터미널을 모두 새로 열고 `claude --version` 확인. 안 되면 "환경 변수" 설정 창에서 추가하거나 `winget install Anthropic.ClaudeCode`. **결과는 아직 모릅니다. [미확인]**
- 참고: Claude가 PowerShell 명령을 CMD 창에 넣으라는 식으로 헷갈리게 안내해서 사용자가 불편을 겪었습니다. 명령마다 **어느 창(CMD/PowerShell)에서 실행하는지** 분명히 적어 주세요.

## 10. 대화가 멈춘 지점 (다음에 이어갈 것)
아래는 대화에서 진행 중이던 일입니다. 새로 정한 계획이 아닙니다.
1. 사용자 컴퓨터의 Claude Code PATH 등록과 `claude --version` 확인(8-3)
2. 그다음 사용자 컴퓨터에서 omniroute, headroom, claude-mem 설치와 검증(8-2)
3. 오라클 서버 생성 재시도 또는 E2.1.Micro로 생성, 이후 공인 IP 붙이기와 SSH 접속(8-1)
4. 실제 사용자 데이터를 받을 경우의 저장 방식 결정(7-1). 사용자가 아직 고르지 않았습니다.
